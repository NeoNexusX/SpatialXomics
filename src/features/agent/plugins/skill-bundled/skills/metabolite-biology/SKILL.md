# Metabolite biology

Start with the candidate, formula, adduct and ambiguity from `get_annotation` windows / `get_annotation(rowIds=[...])`, or use the identity explicitly supplied by the user. Do not require a loaded dataset for a general molecule question. Use static tissue/acquisition metadata already available; do not invent tissue information.

## Stage 1 — Independent per-molecule analysis

Analyze EACH molecule on its own before any cross-molecule reasoning. For each, collect only the evidence the question needs:

1. **Identity**: `pubchem_compound_lookup(names=[...])` for formula/identifiers and its narrative `description`, and `kegg_compound(ids=[...])` for KEGG identity — synthesize the returned record (name/synonyms, formula, description, structural identifiers) rather than treating formula alone as proof. Do not also compare library mass: it is derived from that same formula, so the comparison is circular. Check returned identities: fuzzy name matches may be derivatives, and sum compositions cover isomer families. A verified C id beats a keyword hit; keyword rank is not identity.
2. **Context**: `hmdb_lookup(ids=[...])` for the archived official profile (taxonomy, roles, tissues, cell locations, pathways, normal concentrations, cross-references). Association is not causation or evidence of abundance in this sample. A missing snapshot or unreachable archive is limited coverage, not biological absence; relay failure returns links and explicitly says the profile was NOT read — never invent profile data. Name mode was removed; resolve HMDB accessions through another source first, then query by id.
3. **Ontology**: `chebi_lookup` when "what role does this molecule have" matters (antioxidant, xenobiotic metabolite, …). Relevance-ranked results are not identity verification.
4. **Pathway membership**: `kegg_compound(ids=[...])` already returns each compound's PATHWAY links — that answers membership for the compounds you are assessing. HMDB pathway lines carry the KEGG map id, so use it directly. `kegg_pathway(membersOf=[...])` runs the other direction, listing a reference map's member compound IDs; it returns 10 members per window, so page through `nextOffset` before claiming a compound is absent from a pathway. To see the compound's position in the map, fetch the diagram with `kegg_pathway(ids=["map..."], withImage=true)` (one map per call); it is a curated schematic, not sample-specific evidence. Membership is targeted evidence, not enrichment or pathway activity.
5. **Literature**: search for evidence about the specific claim you are assessing, choosing keywords from it (molecule, tissue, modality, outcome) — e.g. `europepmc_search(query="taurine kidney cortex MALDI imaging", maxResults=3)`. A title is not evidence. On error or zero hits fall back to `pubmed_search`, then `web_search`; the two literature tiers return abstract text, so use the chain rather than giving up at the first tier, and label web_search results as web-source evidence rather than a peer-reviewed abstract.

`kegg_find(query="glucose phosphate", db="compound")` returns one set of entries matching both keywords. Use separate calls for independent searches. `kegg_pathway(id=...)` returns pathway entry details. `kegg_mass_search(mz=..., adduct="[M+H]+")` searches one peak with one adduct consistent with its polarity. Use `kegg_compound` for candidate names and formulas. Use the annotation library or PubChem for lipids. All KEGG tools query the official REST API at runtime through the application's proxy; use the returned URLs for citations. If the API/proxy/network fails, state that KEGG evidence is unavailable for that attempt — do not interpret failure as biological absence and do not ask the user to build a local index.

Record a per-molecule verdict as you go, using the same closed set as `annotation-review`: `supported but putative` / `conflicting evidence` / `insufficient evidence` / `unsupported`, plus a separate resolution level (composition / class / isomer). Before picking the label, walk the dimensions and keep one short line each — mass evidence, adduct/acquisition fit, spatial evidence, chemical identity, **biological background read together with the ion image and checked against retrieved literature** (during this molecule's own assessment, compare its image region with the tissue localization supported by the literature/HMDB, and check that its composition fits that tissue, matrix and additives), and competing identities. Cite the actual abstract text for the tissue claim; a title or database name is insufficient. Do this spatial–tissue correspondence here rather than deferring it to Stage 2. Mark any dimension you could not check as UNAVAILABLE rather than dropping it. The number of adduct ions carrying the molecule is positive evidence — more ions means better corroboration; a single-ion molecule is not disproved, just less corroborated. Isotope reasoning is out of scope (no envelope fitting or MS/MS on this platform); a missing M+1/M+2 in centroid/processed data is unavailable evidence, not proof of absence. Biological plausibility is a consistency check, never a veto: implausible biology is a question to flag, not a refutation, and plausible biology is not corroboration. Unresolved isomers belong to the resolution level, not to the verdict — they are the normal state of accurate-mass annotation. Low intensity and unavailable database coverage are limitations to state, not downgrades. Every judged molecule, putative ones included, proceeds to Stage 2; only `unsupported` and `conflicting evidence` are held back. A molecule first discovered in Stage 2 must complete the full Stage 1 assessment before receiving a verdict; a formula lookup alone is insufficient.

## Stage 2 — Cross-molecule analysis

Now relate the molecules judged in Stage 1, using the per-molecule evidence you already collected. There is no dedicated enrichment tool; do the association reasoning yourself and present it as descriptive, not statistical. **Any evidence-backed connection counts** — shared pathways are one lens, not the goal. Follow whichever the data actually offers:

- **Class and series**: group by ChEBI role or HMDB taxonomy (chemical class) collected in Stage 1 — several phospholipids or several bile acids is class-level evidence even when individual isomers are unresolved. Within a class, a chain-length or double-bond series is often the stronger pattern.
- **Mass relationships**: recurring differences between the judged ions — CH2 homologues, hydrogenation, adduct or isotope families. These come from the annotation rows you already have, no new query needed.
- **Metabolic relationships**: precursor–product pairs or a shared branch, when the retrieved evidence supports it.
- **Shared origin**: a common matrix, background or contaminant source. A negative association is still a finding worth reporting.
- **Shared pathways**: intersect the PATHWAY links collected in Stage 1 (kegg_compound returns them per compound). A pathway shared by ≥2 independent molecules is worth reporting; state how many molecules map to it out of how many were judged. **An empty intersection is a normal result** — many metabolites share no specific map. Do not query further just to fill this bullet. Use `kegg_pathway(membersOf=[...])` only when you actually want to inspect a pathway of interest.
- **Concentration sanity**: HMDB normal concentrations give expected biofluid ranges; a measured claim wildly outside known ranges deserves a flag, but MSI is not quantitative without standards.
- **Literature**: `europepmc_search` for the joint pattern ("moleculeA moleculeB tissue") only when the co-occurrence claim is decisive for the answer; otherwise rely on the per-molecule literature already retrieved.

If the molecules genuinely have nothing in common, say so — do not invent a link. This is a descriptive count, never a background model, p-values, FDR, or a claim of statistical enrichment or pathway activation.

Cross-molecule conclusions inherit the weakest identity status among their members: a pattern built on unresolved isomers stays putative and isomer ambiguity remains explicit. For a defined statistical test, explain the need for a background set and an actual test rather than performing one implicitly.

`chebi_lookup` returns ontology labels/definitions, not a complete inferred biological-role graph. When HMDB/KEGG coverage is unavailable, `web_search` can discover external sources — state that this is web-source evidence rather than a completed HMDB/KEGG lookup, and retain the candidate identity uncertainty.

## Batch discipline

For PubChem and ChEBI, batch distinct names using the tool’s input window (maximum 25 inputs, default 5 per page, maximum 8). HMDB takes accessions only and is slower: its archive relay allows up to 20 s per accession under a 90 s soft deadline, so send 2-3 accessions per call rather than a full page. KEGG compound and pathway details accept 1–10 IDs per call. For more entries, submit another call. KEGG search and membership windows page the returned matches or members. Read archived evidence via `read_archived_result(archiveId=...)` rather than repeating the original lookup. Avoid querying every database automatically for a narrow question.

Respond with identity and uncertainty, the relevant tissue/function/pathway evidence, retrieved citations, and the verdict labels above. A drug in an undosed sample is a mismatch to investigate; unknown dosing is not proof of misannotation. Keep mass-only candidates putative and avoid isomer-specific claims without resolving data.

## Inline source citations

For literature, database facts and other external evidence, place `[source title](URL)` immediately after the claim it supports. These HTTP(S) Markdown links render as shadcn-vue Inline Citation source cards. An optional short source excerpt can be supplied as `[source title](URL "short source excerpt")`; keep it on one line and escape double quotes. Use the exact title and URL returned by a tool. When only a retrieved PMID or DOI is available, link that exact identifier to `https://pubmed.ncbi.nlm.nih.gov/PMID/` or `https://doi.org/DOI`. Do not invent metadata or quotes, emit Vue/HTML components, or substitute bare URLs, PMID/DOI text, numbered markers or footnotes for the inline link. Multiple supporting sources use separate adjacent links. A search excerpt is not proof that the full paper was read.
