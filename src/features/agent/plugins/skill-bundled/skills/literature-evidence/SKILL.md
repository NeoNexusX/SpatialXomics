# Literature evidence

Retrieve evidence **for the specific situation or claim you are assessing** — not a general sweep of a molecule name. Decide the keywords yourself from that claim: molecule (or class), tissue/compartment, modality, outcome or mechanism, and any qualifier that would make the evidence decisive. Reformulate when the first query misses.

Use a fixed provider fallback: **`pubmed_search(query=..., maxResults=3)` first; only if it errors or returns no hits try `europepmc_search`; only if that also errors or returns no hits fall back to `web_search`.** Both literature sources return abstract excerpts, so that fallback does not cost evidence quality — never skip a source on the assumption that it only has metadata, and never fire them at once. `pubmed_search` degrades to title/journal/year/PMID only when its own abstract fetch fails. `web_search` is a different evidence class: it returns web page excerpts, not peer-reviewed abstracts, so label any claim resting on it as web-source evidence. In the answer, name the source only when it matters; do not use tier labels or narrate the fallback order. Both literature sources returning zero hits means no literature was found; both erroring is a coverage gap — neither supports a claim about the biology. A preprint is not peer-reviewed by default.

A nonempty result list is not evidence that the claim is supported. Assess the abstract text against the exact molecule/class, tissue or compartment, modality, and outcome. A title-only record, missing abstract, irrelevant abstract, or contradictory finding does not count as supporting evidence. When the first discovery search returns no abstract that supports the claim, make **one complementary second search** with different claim-focused wording, passing every returned paper's `paper_ids` as `excludeIds` so the same paper cannot be returned again under another provider identifier. The output's `paper_ids` includes PMID, PMCID, DOI, and provider identifier where available. Do not repeat the same search with no exclusions. Stop after that second search; report that no supporting abstract was retrieved after two searches, not that the claim is false. Keep this semantic second pass separate from the provider fallback chain, which still applies only to errors or zero hits.

Use `web_search(query=..., maxResults=3)` for broader source discovery, official methods pages or publisher/database documentation as well. Load `web-research` for that workflow. Exa returns URLs and excerpts, not a guarantee of full-text retrieval: verify scientific findings against available abstract text and do not invent a DOI from a title.

Search the candidate name plus tissue and modality, but start with synonyms and broader biology for common molecules; do not over-constrain the first query with method terms. If too narrow, remove one qualifier or search the molecule class, labeling that evidence as class-level. After two useful reformulations with no supporting result, report the retrieval gap instead of inventing citations. Cancellation, HTTP/auth errors and invalid responses are tool failures, not evidence of no literature or biological absence.

Distinguish direct evidence (the same molecule in the same tissue/modality), transferable evidence (other omics or class-level imaging), mechanism background, and contradicting findings. Separate candidate literature from evidence identifying the measured ion. Confirm isomer/adduct specificity before applying species-specific biology.

Use only the returned text to support claims. Abstracts may be excerpts; avoid assuming omitted methods, tissue context or outcomes. If the needed detail is unavailable, state the limit. **Synthesize before you present or ask:** compare molecule/class, tissue/compartment, modality and outcome against the exact claim, then write a reasoned conclusion with its applicability limit. Do not dump raw abstracts or make the user read the paper for you. Quote at most one short decisive phrase and paraphrase the rest. Use only retrieved PMID/DOI values and working source links; never copy unverified citations from another skill.

For a literature request, give a verdict (supported / partially supported / unsupported / no supporting literature retrieved), a compact finding-and-source table or short bullets when useful, and the main applicability limit. Do not write a paragraph dump of abstracts. For a narrow interpretation, embed one or two supporting citations in the explanation. Do not require a long report for a simple lookup. Ask the user only when a decisive claim remains genuinely unresolved after your synthesis and the tools cannot settle it; present your reasoned conclusion and the remaining uncertainty, not an abstract for the user to judge. A user's relevance confirmation does not upgrade the evidence class.

## Inline source citations

For literature, database facts and other external evidence, place `[source title](URL)` immediately after the claim it supports. These HTTP(S) Markdown links render as shadcn-vue Inline Citation source cards. An optional short source excerpt can be supplied as `[source title](URL "short source excerpt")`; keep it on one line and escape double quotes. Use the exact title and URL returned by a tool. When only a retrieved PMID or DOI is available, link that exact identifier to `https://pubmed.ncbi.nlm.nih.gov/PMID/` or `https://doi.org/DOI`. Do not invent metadata or quotes, emit Vue/HTML components, or substitute bare URLs, PMID/DOI text, numbered markers or footnotes for the inline link. Multiple supporting sources use separate adjacent links. A search excerpt is not proof that the full paper was read.
