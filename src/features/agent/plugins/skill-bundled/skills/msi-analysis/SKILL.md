# MSI analysis

Use static metadata already in Dataset Context. Call `get_page` once when the request depends on the current selection or annotation results; reuse that snapshot within the turn unless the data changes. Its annotation block is a fixed rank 1-10 preview — page deeper windows with `get_annotation(rankFrom=..., rankTo=...)`. These tools read data and render images; they do not run preprocessing, change annotations, or perform new clustering.

## Choose the next evidence

- Dataset summary: use injected instrument, polarity, dimensions, pixel size and mass range. Call `get_dataset` for the full dataset info panel JSON (attrs, acquisition, source file, methods, display range); use it only when the injected summary or the page snapshot is not enough.
- Quality or dominant ions: `get_mean_spectrum_top_peaks(offset=..., limit=..., mzMin=..., mzMax=...)` reads the continuous-mode mean spectrum, ranked by descending intensity and paged by a zero-based window (default rank 1-10; offset reaches any rank). Omit bounds unless needed. A processed dataset may expose TIC without extractable ion images.
- Spatial questions: `get_ion_image_by_mzs(mzs=[...])` returns images and statistics for 1–9 explicit m/z values; `get_ion_image_by_ranks(ranks=[...])` does the same for annotation rows, grouping rows that share an observed m/z. Both fix display to p99 and use a shared range; at most 4 separate panels, otherwise a 2-column montage. **Batch 6 targets per call** — 4 fills the separate-image limit and 6 fills the montage evenly; odd counts and larger batches leave a ragged grid. Raster hotspots are zero-based; `get_pixel_spectrum(x=..., y=..., offset=..., limit=...)` uses one-based acquisition coordinates and attaches a full-spectrum stick plot per pixel (window peaks highlighted). Do not interchange them without a coordinate mapping.
- Selected-ion detail (display parameters, spectrum area, channels, ROI): `get_ion` re-renders the current ion with the user's real display parameters and reports the full ion view. Processed-data TIC also comes from `get_ion`.
- Segmentation: `get_kmeans` gives clusters with colors and selected ids plus the overlay image; `get_umap` gives overlay status plus its image. Neither exposes anatomical labels or quantitative inter-ion correlation.

## Annotations and identity

If annotations exist, start with `get_annotation` (default window: rank 1-10; `rankFrom`/`rankTo` are an inclusive 1-based rank range reaching any rank, e.g. rank 20-30 = rankFrom 20 + rankTo 30). One row is one adduct ion. Rows are full JSON: total score `totalScore`, target-decoy `q`, mass score `massScore`, `adductFit`, spatial `spatialScore` and `chaos`, plus `siblings` — the molecule's other adduct ions, whose count is positive corroboration. Missing spatial scores or q-values mean unavailable evidence; a `spatialScore` at the `0.2·chaos` floor means spatial evidence is unavailable, not weak. The same formula can have multiple isomer candidates. The panel header reports the current filters and the visible row count; the window itself always pages the FULL result set, independent of the table filters.

Read exact rows with `get_annotation(ranks=[...])` for rows you will discuss; exact selectors conflict with rankFrom/rankTo. Nearest-peak m/z lookup was removed because it can hide competing assignments. Load `annotation-review` for a full review, or `adduct-isotope-analysis` for an adduct question.

When there are no annotations, report that fact. For de novo matching against a lipid or user-supplied database, ask the user to run the annotation panel, then inspect its candidate rows. Use `kegg_mass_search(mz=..., adduct="[M+H]+")` for one observed peak and one adduct consistent with the acquisition polarity. It returns KEGG small-molecule candidates ranked by mass error. Choose each additional adduct hypothesis explicitly. Ask for acquisition polarity if unavailable. `pubchem_formula_search` requires an existing molecular formula and cannot infer one from m/z. Accurate mass and database presence establish candidates, not unique identities.

## Biology and efficient lookup

Choose sources that answer the user's question: `pubchem_compound_lookup(names=[...])` for named compound identity/context; `hmdb_lookup(ids=[...])` for archived tissue/disease profiles; `kegg_find`/`kegg_compound(ids=[...])`/`kegg_pathway` for KEGG evidence; `chebi_lookup` for ontology definitions. Preserve lipid shorthand/class evidence from annotation rows rather than treating a sum composition as a unique PubChem identity. For PubChem and ChEBI, batch distinct names and use their input pagination (up to 25 inputs, default 5 per page, maximum 8). Add `withImage=true` to `pubchem_compound_lookup` when a report needs the molecule's 2D structure: one PNG per returned CID, 1–4 names per call and no offset/limit; the structure shows what the name resolved to, not proof of identity. HMDB takes accessions only; send 2–3 per call because the archive relay is slow. KEGG accepts one keyword expression per search and up to 10 IDs per detail request. For a compound's pathway membership read the `pathways` list from `kegg_compound`; to scan whether a pathway is represented across all annotations use `kegg_pathway_annotations(pathwayId="map...")`. `kegg_pathway(membersOf=[...])` remains the raw paged member list; an unexhausted window is never evidence of absence. Use `read_archived_result(archiveId=..., offset=...)` for a complete archived item; reloading the original query does not recover its truncated part. Large pathways page: when `scanComplete` is false the counts are LOWER BOUNDS — call again with `memberOffset=nextMemberOffset` and union member ids across pages before reporting a total. Formula-only isomer hits stay in `formulaOnlyCandidateCount`, never in the confirmed count.

Report ambiguous KEGG matches. An API/proxy failure means unavailable evidence, not an unmapped molecule; never request a local KEGG index build.

For a biological claim, retrieve evidence for that specific claim with `pubmed_search(query=..., maxResults=3)`, choosing keywords from the claim itself (molecule, tissue, modality, outcome); fall back to `europepmc_search` then `web_search` on error or zero hits. When reviewing molecules, every judged molecule gets a literature attempt, including common ones. Load `literature-evidence` for a literature-focused task. Both literature sources return abstract excerpts — metadata alone cannot substantiate a detailed mechanism, so read the returned text rather than the title; label `web_search` findings as web-source evidence. Synthesize the retrieved text into a reasoned conclusion before presenting it or asking the user; do not dump abstracts. Cite only retrieved supporting text and distinguish tissue-specific observations from general background.

For current methods documentation, database instructions or broader source discovery, use `web_search` (Exa); load `web-research` when the task centers on finding web sources. Search public method/molecule descriptions, not private sample data, and cite only the retrieved sources.

## Confirm the weak links with the user

Finish the evidence gathering first — a failed tool is recorded as a coverage gap and the analysis continues; never block in the middle of a check. Then reason through the outstanding items yourself. Ask the user only when a decisive issue remains genuinely unresolved after your analysis and the tools cannot settle it; put those items in ONE `ask_user_question` call (at most 4 questions). Ask about three things only:

1. **An identity match you could not settle** — first compare the returned PubChem/ChEBI record against the candidate yourself. Ask only when name/synonyms point elsewhere, formula disagrees, or the name covers several structures and you cannot decide. Show your reasoned comparison with the returned name, id, formula and structural identifier, and ask whether it is the molecule under discussion.
2. **A literature conclusion you could not settle** — first synthesize the retrieved abstracts into a judgment about the exact claim. Ask only about the decisive claim that would change a conclusion, at most 1-2 per turn, and only when contradictory or insufficient evidence leaves you genuinely unable to decide. Present your reasoned conclusion and remaining uncertainty, with at most one short decisive excerpt and its URL — not a raw abstract for the user to judge. A positive answer does not upgrade an abstract into confirmed evidence.
3. **A proxy/network failure the user can rescue by pasting** — give the exact page URL the tool returned and name the one section you need (the answer box holds 2000 characters). Never do this for a 404 or an empty record: that is a coverage gap with nothing to copy. Pasted content is user-provided evidence, labelled "user-provided, excerpted from \<URL\>", kept apart from sources you retrieved.

The first option carries `(Recommended)` and must be the **conservative default** — `treat as unverified` / `not enough to judge` / `skip and continue` — never `same molecule` or `supports the claim`. On timeout the recommended option is auto-submitted, so a confident recommendation would fabricate a confirmation nobody gave. A skipped item is not permission; an `auto: true` item must be reported as a default you proceeded with, not as the user's judgement. Ask nothing when your synthesis settles the issue or nothing is outstanding.

Do not ask for facts the tools read: organism, organism part, condition, MALDI matrix, matrix application and solvent are in `get_page`'s `dataset.sourceFile`, with matrix/solvent also in `acquisition`. Read them first and ask only if a field is actually empty. Merely reporting a failure and where to look is a statement — put the URL in your answer and continue rather than opening a question card. `annotation-review` carries the full wording of these three checks.

## Quality and reporting

Separate observations from interpretations. A nonzero-pixel mean is not a background estimate or signal-to-noise measurement. Nonzero fraction depends on acquisition, processing and masking; it is not a biomarker classifier. Compare images for matrix edges, isolated hot pixels, gradients and common background patterns. Subpixel features are not resolved anatomy. Do not infer anatomy from cluster colors alone.

Describe preprocessing only if its execution is recorded. Recommendations depend on data mode, noise, spatial resolution and the question; explain the reason and avoid claiming a fixed pipeline has already run.

For a report include dataset and recorded preprocessing, key ions with candidate/adduct and observed evidence, spatial structure, targeted biological interpretation with retrieved sources, and limits/confirmation needs. For a narrow request return only the relevant findings. Accurate-mass annotations remain putative; isomer-specific claims require resolving evidence such as MS/MS or standards.

## Inline source citations

For literature, database facts and other external evidence, place `[source title](URL)` immediately after the claim it supports. These HTTP(S) Markdown links render as shadcn-vue Inline Citation source cards. An optional short source excerpt can be supplied as `[source title](URL "short source excerpt")`; keep it on one line and escape double quotes. Use the exact title and URL returned by a tool. When only a retrieved PMID or DOI is available, link that exact identifier to `https://pubmed.ncbi.nlm.nih.gov/PMID/` or `https://doi.org/DOI`. Do not invent metadata or quotes, emit Vue/HTML components, or substitute bare URLs, PMID/DOI text, numbered markers or footnotes for the inline link. Multiple supporting sources use separate adjacent links. A search excerpt is not proof that the full paper was read. Text the user pasted in answer to a question is user-provided evidence: link the page it came from but say so explicitly, and never present it as a source you retrieved.
