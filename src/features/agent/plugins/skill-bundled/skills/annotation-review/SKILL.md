# Review existing annotations

Treat annotation rows as hypotheses. Read `get_page` once to confirm annotations; its annotation block previews rank 1-10 and is often enough to pick the rows under scrutiny. Page with `get_annotation` only when the preview does not cover what you need: ranks beyond it (too few distinct molecules in the top 10 — request the next range directly, `rankFrom=11, rankTo=20`), or a preview marked `truncated`/`omittedRows` whose rows lost `candidates`, `siblings`, `samePeak` or `missingAdducts`. The range is 1-based and inclusive on both ends, matching the `rank` field on every row. Do not re-read rank 1-10 when the preview already returned them intact. If there are no annotations, explain that a review needs annotation results; offer de novo matching only when that addresses the user's request.

Walk the ranking in order: take a window of 10, run the knowledge checks on it, and stop once roughly ten distinct molecules have their own verdict. `supported but putative` counts as delivered. Accurate-mass annotation is always putative, so waiting for ten fully resolved molecules never terminates. Advance with `paging.nextRank` only when a check actually contradicts the rows — a confirmed identity mismatch, or a competing identity that external evidence favours — or when the window holds too few distinct molecules to answer the request. Unresolved isomers, a missing sibling adduct, low intensity and an uninformative spatial score are NOT reasons to page further. A window may return fewer rows than the requested range — follow the cursor, not the requested `rankTo`. Do not jump out of rank order to fetch the rows named in `samePeak`; report them as alternative explanations and keep the row putative. An unexamined competitor alone is not `insufficient evidence`; downgrade to `conflicting evidence` only when a check actually favours it. Later windows surface those competitors on their own.

Use `get_annotation(rowIds=[...])` only to re-read rows already discussed or named by the user, never to pull competitors. Exact lookup takes `rowIds` only; nearest-peak m/z lookup was removed because it can hide a competing row. Exact selectors conflict with rankFrom/rankTo — pass one mode per call. Read an archived item with `read_archived_result(archiveId=...)` when essential evidence was shortened.

Assess each candidate molecule independently before relating any of them to each other: run the engine reading and the knowledge checks for one molecule without borrowing another molecule's verdict, and merge its sibling adduct rows into a single molecule entry. Only after every selected molecule has its own verdict do you look for connections between them (see Association analysis). A molecule that first surfaces during that association pass goes back through its own independent assessment; never settle it inline.

## Evaluate evidence

- Read actual score weights from the top-list header. `s` is total score, `m` mass error, `fit` acquisition/adduct plausibility, `ch` spatial coherence, `col` best sibling-image correlation, `q` target-decoy estimate. Missing scores are unavailable. A q-value is not the probability that a particular named isomer is correct.
- `spatialScore = 0.2·chaos + 0.8·coloc`, and `coloc` scores 0 when it is null or r ≤ 0.1. So when `coloc` is null — typically a molecule with no detected sibling adduct — `spatialScore` collapses to the `0.2·chaos` floor (≈0.20) and carries **no spatial information at all**. Read that floor as spatial evidence UNAVAILABLE, never as weak spatial evidence, and never let it lower a verdict. `chaos` alone rarely discriminates: it sits near 0.99 for most rows. Judge spatial support from `get_ion_image_by_rowIds`, not from a floor value. The same floor also depresses `totalScore`, so a low rank caused by a missing sibling is a ranking artifact, not evidence against the identity — say so rather than demoting the row.
- Intensity is not a confidence criterion. A weak ion is still a valid putative annotation; low intensity limits detectability and image quality, not identity. Do not use it to downgrade a verdict.
- Same-formula siblings can corroborate an ion family **only after excluding an isotope explanation**. A high image correlation is expected for an isotope and its parent and is not independent adduct evidence. Check the observed spacing against the isotope ladder and the intensity ratio before accepting a sibling label. In particular, a peak about +1.00336 Da above a stronger neighbour may be its ¹³C M+1 peak, not a chloride adduct of another molecule. Competing same-peak rows, inconsistent sibling distributions, or a formula mismatch require explanation. Missing adducts alone do not disprove an identity.
- **Missing isotope evidence is not negative evidence.** In centroid/processed data, a low-abundance isotope peak may fall below the peak-picking threshold. If the requested m/z has no axis point, an image target fails, or the peak table does not list the expected M+1/M+2, write "isotope evidence unavailable/not detected above the processing threshold" — never "the isotope is absent" or use that alone to refute a formula. A negative isotope argument needs a defensible detection limit/noise estimate and an extraction window around the real axis, not a failed image call.
- Inspect `get_ion_image_by_rowIds(rowIds=[...])` when spatial evidence affects the verdict. For unannotated peaks use `get_ion_image_by_mzs(mzs=[...])`. **Batch 6 targets per call** — 4 fills the separate-image limit and 6 fills the 2-column montage evenly; odd counts and larger batches leave a ragged grid. Both tools fix display to `p99` and use a shared color range so intensities stay comparable across images. Coherent background or matrix patterns can also score highly. Cluster sizes cannot prove anatomical localization.
- `origin` orders candidate names as a prior; it is not spectral evidence, and it is sometimes mislabelled in the library. An implausible origin (a plant natural product, reagent or drug in an undosed control) is a question to flag, not a refutation: on its own it never yields `unsupported` or "false positive". Check the displayed name and plausible alternative candidates, including isomers. Sum composition does not resolve fatty-acyl positions or stereochemistry.

## Target knowledge checks

For PubChem and ChEBI, batch distinct names (up to 25 inputs, default 5 queries per page, maximum 8). HMDB is the exception: its archive relay takes up to 20 s per accession under a 90 s soft deadline, so send only 2-3 accessions per call and pick the molecules whose tissue context actually matters — a batch of 8 times out and returns no profile at all. Submit independent KEGG keyword searches separately. Use up to 10 IDs per KEGG compound or pathway detail call.

Use `pubchem_compound_lookup(names=[...])` for named candidate identities and judge the returned record as a whole: whether the returned name/synonyms denote the intended candidate, whether its formula is consistent with the annotation row, what its `description` says about biological context, and whether `inchikey` helps distinguish same-name structures. Formula is one consistency check, not the identity verdict. Add `withImage=true` when the report needs the molecule's 2D structure: it attaches one PNG per returned CID (1–4 names per call, no offset/limit) from the same record as the text, so it shows what the name resolved to — not proof that the resolution was right. A fuzzy name hit may be a related compound or derivative; verify the returned identity before using any mismatch against the row. `description` is background, not proof of the measured species. Library masses are not returned because they derive from the same formula and add no independent evidence; independent mass evidence starts from the observed m/z — the engine's `errPpm`, an isotope ladder, or `kegg_mass_search`. Keep lipid shorthand and class evidence from the annotation result, and do not treat a sum composition as a unique structure. Use `hmdb_lookup(ids=[...])` for tissue/disease context; name mode was removed, so resolve accessions elsewhere first. Substring search results can be related compounds: verify the returned identity. A missing record means limited coverage, not absence from tissue. Call `chebi_lookup` only when an ontology definition or parent class is actually needed; it ranks by relevance and does not verify identity.

For pathway membership, read the `pathways` list returned by `kegg_compound(ids=[...])` — it already answers which pathways that compound belongs to. HMDB pathway lines now carry the KEGG map id, so take that id directly instead of guessing a map from its name; likewise take the KEGG Compound ID from an HMDB profile instead of guessing with `kegg_find`. `kegg_pathway(membersOf=[...])` queries the reverse direction, listing a pathway's members: its window returns 10 compounds by default, so an unexhausted window is never evidence that a compound is absent from the pathway. Page through `nextOffset` before claiming absence. When seeing where the compound sits in the map actually helps the argument, fetch the diagram with `kegg_pathway(ids=["map..."], withImage=true)` (one map per call) and describe what the image shows; a pathway diagram is a curated schematic, not sample-specific evidence. Both directions check selected identities; neither aggregates the annotation set nor performs a statistical enrichment test. Report membership as descriptive evidence only, not pathway activity.

Report ambiguous KEGG matches. An API/proxy failure means unavailable evidence, not an unmapped molecule; never request a local KEGG index build.

When same-peak rows genuinely compete and the annotation fields cannot separate them (`samePeak` carries only name/adduct/origin), one `kegg_mass_search(mz=..., adduct=..., ppm=...)` on that observed mass is a cheap independent check: it ranks library candidates by mass error alone, ignoring the engine's spatial and adduct terms. Use it to see whether an unannotated or low-ranked competitor fits the peak better. A hit is a candidate, not a unique identity, and a mass-only search does not override a spatial or adduct argument — report what it changes and what it cannot settle.

Retrieve literature **for the specific claim or observation you need to settle** — a decisive tissue-specific assignment, a surprising candidate, or a spatial pattern you must interpret. Set the keywords yourself from that claim (molecule or class, tissue/region, modality, outcome); do not just search the molecule name. Use a fixed fallback chain: **`europepmc_search` first; only if it errors or returns no hits try `pubmed_search`; only if that also errors or returns no hits fall back to `web_search`.** Both literature tiers return abstract text, so that fallback does not cost evidence quality — do not skip a tier because you assume it lacks abstracts, and do not run them in parallel. `web_search` returns web excerpts rather than peer-reviewed abstracts: label evidence obtained that way as web-source evidence. Say which tier actually served the evidence and why the earlier ones did not. Both literature tiers returning zero hits means no literature was found; both erroring is a coverage gap. Neither is evidence that the claim is wrong. Cite only findings supported by returned text; a database name or paper title cannot confirm the measured species.

## Confirm the weak links with the user

Three points in this workflow rest on judgement the tools cannot settle. Run B1-B7 to completion first — **never block in the middle of a check**: a failed tool is recorded UNAVAILABLE and the scan continues. Then, before assigning verdicts, put the outstanding items to the user in ONE `ask_user_question` call (at most 4 questions), apply the answers to the affected dimensions, and only then give verdicts. If nothing is outstanding, do not ask at all.

**1. A B3 identity match you could not settle.** Ask only when the returned record does not obviously denote the intended candidate: the returned name/synonyms point elsewhere, the formula disagrees, or the same name covers several structures. A returned name identical to the candidate with a matching formula and a single structure needs no question. Show what actually came back — returned name, CID, formula, `inchikey` — and ask whether it is the molecule under review. Options: `treat as unverified, record this dimension UNAVAILABLE (Recommended)` / `same molecule` / `related compound or derivative, not the same molecule` / `salt or adduct form, same parent`. Until the user answers, never use a mismatch from an unverified hit against the row.

**2. Whether the retrieved literature fits the claim.** Ask only about the **decisive** claim — the one that would flip a verdict or carry the spatial–tissue correspondence — at most 1-2 per turn, not every citation. State the claim, then quote the returned abstract excerpt with its URL so the user can judge in seconds or open the paper. Options: `not enough to judge, record UNAVAILABLE (Recommended)` / `supports the claim` / `supports only a weaker claim, soften the wording` / `not relevant, search again with different keywords`. The user is judging relevance, not reading the full paper for you: a `supports the claim` answer does **not** upgrade the evidence class. It is still an abstract — record it as "the user confirmed this abstract is relevant to the claim", never as "the literature confirmed it".

**3. A failed knowledge tool the user can rescue by pasting.** Only for a proxy/network failure, never for a 404 or an empty record — that is a coverage gap and the page holds nothing to copy. Give the exact page URL the tool returned (`https://www.hmdb.ca/metabolites/HMDB…`, the KEGG entry page, the PubChem CID page, the PubMed record) and name the **one section** you need: "paste the Tissue Locations lines", "just the KEGG Compound ID line". The answer box holds 2000 characters, so a whole profile will not fit. Options: `skip, record UNAVAILABLE and continue (Recommended)` / `I will paste it` with the free-text box. Content the user pastes is **user-provided evidence, not a tool result**: label it "user-provided, excerpted from \<URL\>" and keep it apart from the sources you retrieved yourself.

Rules for all three:

- The first option carries `(Recommended)` and must be the **safe default for a user who walked away** — never `same molecule` or `supports the claim`. On timeout the recommended option is auto-submitted, so a confident-sounding recommendation would fabricate a confirmation nobody gave. Every default above is the conservative one, so an unanswered card leaves the review exactly where it would have been without asking.
- An item with empty `selected` and no `custom` is a skip: continue without it and do not ask again. An item with `auto: true` was filled in by the timer — say you proceeded with the default rather than presenting it as the user's judgement.
- Ask about these three things only. Do not ask for facts the tools already read: organism, organism part, condition, MALDI matrix, matrix application and solvent are in `get_page`'s `dataset.sourceFile` (and matrix/solvent also in `acquisition`) — read them, and only ask if the field is actually empty. Do not ask the user to choose a verdict label, to approve a read-only tool call, or which language to write in.
- Merely telling the user a tool failed and where to look is a statement, not a question: put the URL in your answer and continue. Use `ask_user_question` only when you will actually wait for the paste.

## Verdicts

Before choosing a label, run through the dimensions below — **one short line each**. A dimension you could not check is written down as UNAVAILABLE; never fill it from another molecule's result, and never drop it silently.

| Dimension | What to say, briefly | Evidence step |
|---|---|---|
| Mass evidence | `errPpm` against instrument resolution; any isotope-ladder or independent mass-search finding | B1 / X4 |
| Adduct & acquisition | `adductFit` against polarity, matrix and additives; sibling `coloc` as cross-row support | B1 |
| Spatial evidence | what the ion image actually shows; a floor `spatialScore` means spatial evidence is UNAVAILABLE, not weak | B2 |
| Chemical identity | whether the returned external record denotes the intended candidate and is consistent with the row (name/synonyms, formula, description, structural identifiers); candidate/isomer count feeds the resolution level, not the verdict | B3 / B5 |
| **Biological background (read WITH the image and checked against the literature)** | During this molecule's own assessment, compare the region the image shows with where retrieved literature and HMDB place this molecule; check whether its composition fits that tissue, matrix and additives. Separate the image observation from the literature interpretation and cite the supporting text | B2 + B4 / B7 |
| Competing identities | the `samePeak` alternatives, and whether any check actually favours one | B1 / X4 |

**Do the spatial–tissue correspondence here, per molecule; do not save it for the association pass.** Retrieve literature when it is needed to judge whether that image region is compatible with the molecule's recorded localization. A database name, paper title or generic class description is not enough: the returned abstract or profile must support the tissue claim. If the literature does not address this sample or region, mark that correspondence unavailable.

**The biological-background dimension is a consistency check, never a veto.** An implausible biology — a drug or plant product in an undosed control, a compartment the tissue should not contain — is a question to flag and carry into the unresolved-identity section. On its own it never produces `unsupported` or "false positive", and it does not demote a verdict whose other dimensions agree. It becomes `conflicting evidence` only when a check positively favours a competing identity. Conversely, a plausible biology is not corroboration: matrix and background species are biologically plausible almost anywhere.

Give every molecule exactly one verdict from this closed set, using these labels verbatim in the user's language — do not invent intermediate wording or append qualifiers such as `(flagged)` to a label. Put flags and caveats in the evidence prose or unresolved-identity section:

| English | 中文 | Meaning |
|---|---|---|
| `supported but putative` | 支持但推定 | Engine and external checks agree; identity not confirmed by MS/MS or a standard |
| `conflicting evidence` | 证据冲突 | A check actively contradicts the row, or favours a competing identity |
| `insufficient evidence` | 证据不足 | The decisive check could not be run and nothing else settles it |
| `unsupported` | 不支持 | Positive evidence against the assignment after verifying the returned record is the intended candidate (e.g. a confirmed identity/structure mismatch, not a fuzzy name hit or circular mass comparison) |

Report the **resolution level** on a separate axis: composition / class / isomer (组成级 / 类别级 / 异构体级). Unresolved isomers are the normal state of accurate-mass annotation — record them in the resolution level and in the follow-up recommendations, and keep the verdict `supported but putative`. A long candidate list, an unresolved sn-position or double-bond position, an unexamined same-peak name, a missing sibling adduct, a floor `spatialScore`, low intensity and an implausible `origin` are **not** downgrades. Unavailable evidence (a timed-out HMDB or a failed proxy) is a coverage gap to state, not `insufficient evidence` against the molecule, as long as the remaining checks agree.

## Association analysis

Only after every selected molecule has its own verdict. **Each molecule's own spatial–tissue correspondence and literature-supported biological background were already assessed independently; do not reopen them here.** This pass only compares molecules with one another. The goal is **any connection the collected evidence actually supports**. Work the lenses in two tiers: **lead with the first tier**, then add second-tier lenses only when they say something the first tier did not. Skip a lens the data cannot support rather than forcing it.

**Tier 1 — lead with these:**

- **Spatial co-distribution — SHOW the images.** Wherever the judged molecules share a region, render that group with `get_ion_image_by_rowIds(rowIds=[...])` (fixed p99/shared range, batch 6 targets, 2-column montage above 4 images) so the reader sees the overlap instead of taking your word for it. Reuse the B2 images you already have; fetch only the missing ones. State what the images show before interpreting it. Without histology registration or an anatomical mask, use observational terms such as "central band" and "outer/cortex-like region"; do not assert inner medulla or renal pelvis as established anatomy. Remember that sharing an anatomical compartment is NOT independent corroboration between those molecules.
- **Shared KEGG pathways or compound classes.** Intersect the `pathways` lists already returned by `kegg_compound` in B5 — no extra query. To check whether a molecule seen in a pathway or in the literature is actually in this dataset, use `get_annotation(molecules=[...])`: by default it matches whole candidate names, library ids and exact formulas across the FULL loaded annotation result and returns compact row/rank hits. `matchMode="contains"` is opt-in exploratory substring discovery and can return derivatives (for example, methylxanthine for xanthine); never treat those as the queried molecule. A candidate-name hit means the name occurs in that row, not that the isomer was independently identified. Read full rows with `rowIds` and complete the independent assessment before using a newly surfaced molecule. A miss is an annotation-result miss, not biological absence. An empty pathway intersection is a normal result, not a gap to fill: many small metabolites and lipids share no specific map. Report the denominator (how many judged molecules were mapped, how many hit).

**Tier 2 — add when they carry new information:**

- **Shared adduct ions.** The same molecule carrying several adducts, or the same adduct family recurring across molecules. Read the sibling `coloc` values and adduct labels you already have.
- **Precursor–product or shared metabolic branch**, when the B4/B5 identities actually support it.
- **Common matrix, background or contaminant origin.** B2 images plus B3 identity. A negative association is still a finding.

Do not run extra KEGG queries just to produce a shared-pathway section, and do not keep widening the claim until something shows up. Report the denominator for whatever you did check. If the molecules genuinely have nothing in common, say so and stop.

Every association must rest on evidence already collected — never invent a link to fill the section. Co-occurrence is not enrichment, activation, flux or causation, and spatial co-distribution is not proof of identity. A molecule that first surfaces during this pass goes back through its own complete independent assessment (engine evidence, image, identity, biological background/literature and competitors) before it can receive a verdict or enter the association table. A formula lookup alone is not that assessment; leave it as an unresolved candidate if the full pass was not run.

## Respond

Before writing a full review report, load its template: `skill(name="report-writing", resourceId="report-template:annotation-review:en")`. That is the only template resource. The scaffold is in English, but write the report in the user's language, translating headings and prose while keeping molecule names, formulas and adduct labels unchanged. That call returns the template scaffold alone; call `skill(name="report-writing")` separately if you also need the shared writing rules. Organize the report under the template's five sections; do not improvise your own section layout, and do not write the report before loading the template. A short answer to a narrow question about one row does not need the template.

Use the original molecule names returned by the annotation/library tools — do not translate molecule names into Chinese or another language. Translate explanatory prose and the fixed verdict labels only; shorthand such as LysoPE(20:4), adduct labels and formulas stay unchanged. Use the template's ion table, with the verdict labels above plus the resolution level. In each molecule's section, introduce the molecule first — basic information, structure, chemical information, biological information — and only then list the evidence dimensions. Every evidence dimension that rests on an image must show that image: the molecule's own ion image for spatial evidence, parent and isotope images together for an isotope-ladder argument, sibling images for a co-localization argument, and the competing ion images when a competitor was compared. Reuse the images already fetched and batch 6 targets per call. For the structure bullet, fetch the 2D structure with `pubchem_compound_lookup(names=[...], withImage=true)` — one image per returned CID, 1–4 names per call, no offset/limit — and say which CID it belongs to; the image depicts whatever the name resolved to, so it is not identity proof. If that lookup failed or the image was unavailable, link the PubChem/ChEBI/KEGG record page and say the structure was not retrieved. Never draw one or embed an image URL no tool returned. List each molecule once even when several adduct rows support it, and record the rank range actually scanned and how many distinct molecules were judged — putative molecules count toward that total. Explain disagreements and candidate alternatives. Report associations only after the independent verdicts, tier-1 lenses first, attaching ion images for any spatial co-distribution group, with the denominator of how many molecules were checked; co-occurrence is not enrichment, activation, flux or causation. Include pathway membership and coverage when you queried KEGG; do not imply checks you did not run. Recommend MS/MS, standards or isomer resolution for specific remaining uncertainty. Avoid fixed score cutoffs as universal identification rules.

## Inline source citations

For literature, database facts and other external evidence, place `[source title](URL)` immediately after the claim it supports. These HTTP(S) Markdown links render as shadcn-vue Inline Citation source cards. An optional short source excerpt can be supplied as `[source title](URL "short source excerpt")`; keep it on one line and escape double quotes. Use the exact title and URL returned by a tool. When only a retrieved PMID or DOI is available, link that exact identifier to `https://pubmed.ncbi.nlm.nih.gov/PMID/` or `https://doi.org/DOI`. Do not invent metadata or quotes, emit Vue/HTML components, or substitute bare URLs, PMID/DOI text, numbered markers or footnotes for the inline link. Multiple supporting sources use separate adjacent links. A search excerpt is not proof that the full paper was read. Text the user pasted in answer to a question is user-provided evidence: link the page it came from but say so explicitly, and never present it as a source you retrieved.
