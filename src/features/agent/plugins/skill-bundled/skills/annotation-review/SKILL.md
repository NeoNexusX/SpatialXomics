# Review existing annotations

## Workflow

Run the steps in this order. The labels are the evidence steps cited in the Verdicts table.

| Step      | What you do                                                                                                                                                  | Tool                               |
| --------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------ | ---------------------------------- |
| **A1**    | Load this skill                                                                                                                                              | `skill`                            |
| **A2**    | Confirm annotations and read the dataset context once                                                                                                        | `get_page`                         |
| **A3**    | Take a window of 10 rows (rank 1–10 first; next windows via `paging.nextRank`)                                                                               | `get_annotation(rankFrom, rankTo)` |
| **B1**    | Read the engine scores of the window: weights, `errPpm`, `adductFit`, `spatialScore`, `siblings`, `samePeak`                                                 | — (from A3)                        |
| **B2**    | Render ion images for the window's molecules — one call per molecule carrying its own rows, so each image belongs to one molecule                            | `get_ion_image_by_ranks`           |
| **B3**    | Identity check of the window's candidate names, batched                                                                                                      | `pubchem_compound_lookup`          |
| **B4**    | Tissue/disease context for the molecules whose tissue matters, 2–3 accessions per call                                                                       | `hmdb_lookup`                      |
| **B5**    | Pathway membership: resolve KEGG ids, then read compound records                                                                                             | `kegg_find` → `kegg_compound`      |
| **B6**    | Only when a pathway's members or map are needed                                                                                                              | `kegg_pathway`                     |
| **B7**    | Literature for EVERY molecule in the window, focused on its spatial–tissue/biological claim; fixed chain `pubmed_search` → `europepmc_search` → `web_search` | literature tools                   |
| **B8**    | Give each molecule in the window its own verdict (one per molecule, adduct rows merged)                                                                      | —                                  |
| **B9**    | Decide whether another window is needed (see the rules below)                                                                                                | —                                  |
| **X1–X6** | On demand only: archived results, dataset details, named rows, same-peak mass check, reverse molecule lookup, asking the user                                | see the relevant section           |

A2 → A3 → B1–B7 is one pass over one window. Run B1–B7 to completion for the window before B8; never block in the middle because a tool failed (record the gap and continue). B7 is mandatory for every judged molecule, including common ones — do not skip a literature attempt because the molecule is familiar. After all windows, reason through the outstanding weak links yourself; ask the user only about genuinely unresolved decisive issues (X6), then the association analysis (C), then load the report template and write (D).

Steps that return images (B2, B3 with `withImage=true`, B6 with `withImage=true`) produce the figures the report must embed under each molecule's evidence — see Respond.

Treat annotation rows as hypotheses. Read `get_page` once to confirm annotations; its annotation block previews rank 1-10 and is often enough to pick the rows under scrutiny. Page with `get_annotation` only when the preview does not cover what you need: ranks beyond it (too few distinct molecules in the top 10 — request the next range directly, `rankFrom=11, rankTo=20`), or a preview marked `truncated`/`omittedRows` whose rows lost `candidates`, `siblings` or `samePeak`. The range is 1-based and inclusive on both ends, matching the `rank` field on every row. Do not re-read rank 1-10 when the preview already returned them intact. If there are no annotations, explain that a review needs annotation results; offer de novo matching only when that addresses the user's request.

Walk the ranking in order: take a window of 10, run the knowledge checks on it, and stop once roughly ten distinct molecules have their own verdict. `supported but putative` counts as delivered. Accurate-mass annotation is always putative, so waiting for ten fully resolved molecules never terminates. Advance with `paging.nextRank` only when a check actually contradicts the rows — a confirmed identity mismatch, or a competing identity that external evidence favours — or when the window holds too few distinct molecules to answer the request. Unresolved isomers, a single detected adduct ion, low intensity and an uninformative spatial score are NOT reasons to page further. A window may return fewer rows than the requested range — follow the cursor, not the requested `rankTo`. Do not jump out of rank order to fetch the rows named in `samePeak`; report them as alternative explanations and keep the row putative. An unexamined competitor alone is not `insufficient evidence`; downgrade to `conflicting evidence` only when a check actually favours it. Later windows surface those competitors on their own.

Use `get_annotation(ranks=[...])` only to re-read rows already discussed or named by the user, never to pull competitors. Exact lookup takes `ranks` only; nearest-peak m/z lookup was removed because it can hide a competing row. Exact selectors conflict with rankFrom/rankTo — pass one mode per call. Read an archived item with `read_archived_result(archiveId=...)` when essential evidence was shortened.

Assess each candidate molecule independently before relating any of them to each other: run the engine reading and the knowledge checks for one molecule without borrowing another molecule's verdict, and merge the several adduct rows carrying the same molecule name into a single molecule entry. Only after every selected molecule has its own verdict do you look for connections between them (see Association analysis). A molecule that first surfaces during that association pass goes back through its own independent assessment; never settle it inline.

## Evaluate evidence

- Read the actual score weights from `panel.weights` (mass / adduct / spatial, normalised). Each row carries `totalScore`, `massScore`, `adductFit`, `chaos`, `spatialScore` and `q`. Missing scores are unavailable. A q-value is not the probability that a particular named isomer is correct.
- When `spatialScore` sits at the `0.2·chaos` floor (≈0.20) it carries **no spatial information at all**. Read that floor as spatial evidence UNAVAILABLE, never as weak spatial evidence, and never let it lower a verdict. `chaos` alone rarely discriminates: it sits near 0.99 for most rows. Judge spatial support from `get_ion_image_by_ranks`, not from a floor value. The same floor also depresses `totalScore`, so a low rank caused by it is a ranking artifact, not evidence against the identity — say so rather than demoting the row.
- Intensity is not a confidence criterion. A weak ion is still a valid putative annotation; low intensity limits detectability and image quality, not identity. Do not use it to downgrade a verdict.
- Judge adduct plausibility from `adductFit` and the acquisition conditions (polarity, matrix, additives). **The number of adduct ions carrying the same molecule is positive evidence**: `siblings` lists that molecule's other adduct rows, including rows outside the current window, so count `siblings.length + 1`. A molecule independently detected as several adduct ions is better corroborated than a single-ion assignment; say how many ions support it. Check that the observed spacings are consistent with the proposed adduct shifts and the acquisition tolerance. Competing same-peak rows or a formula mismatch still require explanation. A molecule with only one detected ion is not disproved — ionization, suppression and detection thresholds limit which adducts appear — but it has less corroboration, and you should say so.
- **Do not build arguments on isotope patterns.** The platform has no isotope-envelope fitting and no MS/MS search, so isotope reasoning is out of scope for now: do not use an isotope ladder to support or refute an identity, and do not gate an adduct assignment on excluding an isotope explanation. **Missing isotope evidence is not negative evidence** either — in centroid/processed data a low-abundance isotope peak may fall below the peak-picking threshold. If the expected M+1/M+2 is not listed, write "isotope evidence unavailable/not detected above the processing threshold", never "the isotope is absent". When a judgement genuinely needs isotope or MS/MS data, name the missing measurement in the recommendations instead of substituting a weaker argument.
- Inspect `get_ion_image_by_ranks(ranks=[...])` when spatial evidence affects the verdict. For unannotated peaks use `get_ion_image_by_mzs(mzs=[...])`. **Group the targets by molecule, not by count**: one call per judged molecule carrying its own adduct rows (commonly 2–3 ranks) — up to 4 targets return separate images, and only a single-molecule group above 4 becomes a 2-column montage of that molecule alone. A montage that mixes molecules cannot be placed under any one molecule's evidence in the report, so do not build one for the report; cross-molecule groups are for the association pass only (see Spatial co-distribution). Both tools fix display to `p99` and use a shared color range so intensities stay comparable across images. Coherent background or matrix patterns can also score highly. Cluster sizes cannot prove anatomical localization.
- **Infer the organ; do not hide behind missing histology.** An organ-level reading is expected whenever the evidence converges: the tissue outline and zoning visible in the ion images, the recorded organism/organism part, and several judged molecules whose retrieved HMDB/literature localization agrees. Name that organ and give its basis in one clause, marked as an inference (form only: "kidney — inferred from the bean-shaped outline, the cortex/medulla-like zonation and the retrieved osmolyte literature"). What stays observational is the finer level the evidence does not reach: without a supporting reference plus a matching image pattern, write "central band" / "outer region" rather than asserting inner medulla or renal pelvis. Missing histology limits how fine the label can be, not whether an organ may be inferred — never write a blanket "no anatomical assignment is possible" limitation, and never let it downgrade a verdict. Write the observational term itself, never the rule behind it: the report says "central band", not "without histological registration this can only be called a central band / inner-medulla-like region, and no finer anatomical subdivision is named".
- `origin` orders candidate names as a prior; it is not spectral evidence, and it is sometimes mislabelled in the library. An implausible origin (a plant natural product, reagent or drug in an undosed control) is a question to flag, not a refutation: on its own it never yields `unsupported` or "false positive". Check the displayed name and plausible alternative candidates, including isomers. Sum composition does not resolve fatty-acyl positions or stereochemistry.

## Target knowledge checks

For PubChem and ChEBI, batch distinct names (up to 25 inputs, default 5 queries per page, maximum 8). HMDB is the exception: its archive relay takes up to 20 s per accession under a 90 s soft deadline, so send only 2-3 accessions per call and pick the molecules whose tissue context actually matters — a batch of 8 times out and returns no profile at all. Submit independent KEGG keyword searches separately. Use up to 10 IDs per KEGG compound or pathway detail call.

Use `pubchem_compound_lookup(names=[...])` for named candidate identities and judge the returned record as a whole: whether the returned name/synonyms denote the intended candidate, whether its formula is consistent with the annotation row, what its `description` says about biological context, and whether `inchikey` helps distinguish same-name structures. Formula is one consistency check, not the identity verdict. Add `withImage=true` when the report needs the molecule's 2D structure: it attaches one PNG per returned CID (1–4 names per call, no offset/limit) from the same record as the text, so it shows what the name resolved to — not proof that the resolution was right. A fuzzy name hit may be a related compound or derivative; verify the returned identity before using any mismatch against the row. `description` is background, not proof of the measured species. Library masses are not returned because they derive from the same formula and add no independent evidence; independent mass evidence starts from the observed m/z — the engine's `errPpm` or `kegg_mass_search`. Keep lipid shorthand and class evidence from the annotation result, and do not treat a sum composition as a unique structure. Use `hmdb_lookup(ids=[...])` for tissue/disease context; name mode was removed, so resolve accessions elsewhere first. Substring search results can be related compounds: verify the returned identity. A missing record means limited coverage, not absence from tissue. Call `chebi_lookup` only when an ontology definition or parent class is actually needed; it ranks by relevance and does not verify identity.

For pathway membership, read the `pathways` list returned by `kegg_compound(ids=[...])` — it already answers which pathways that compound belongs to. HMDB pathway lines now carry the KEGG map id, so take that id directly instead of guessing a map from its name; likewise take the KEGG Compound ID from an HMDB profile instead of guessing with `kegg_find`. To ask whether a pathway is represented across the dataset, use `kegg_pathway_annotations(pathwayId="map...")`: it scans EVERY loaded annotation row, not only the reviewed rank window, and reports matched ranks, distinct member counts and coverage. `kegg_pathway(membersOf=[...])` remains the raw paged member list; an unexhausted window is never evidence that a compound is absent from the pathway. When seeing where the compound sits in the map actually helps the argument, fetch the diagram with `kegg_pathway(ids=["map..."], withImage=true)` (one map per call) and describe what the image shows; a pathway diagram is a curated schematic, not sample-specific evidence. Report membership as descriptive evidence only, not pathway activity or statistical enrichment. Large pathways page: when `scanComplete` is false the counts are LOWER BOUNDS — call again with `memberOffset=nextMemberOffset` and union member ids across pages before reporting a total. Formula-only isomer hits stay in `formulaOnlyCandidateCount`, never in the confirmed count.

Report ambiguous KEGG matches. An API/proxy failure means unavailable evidence, not an unmapped molecule; never request a local KEGG index build.

When same-peak rows genuinely compete and the annotation fields cannot separate them (`samePeak` carries only name/adduct/origin), one `kegg_mass_search(mz=..., adduct=..., ppm=...)` on that observed mass is a cheap independent check: it ranks library candidates by mass error alone, ignoring the engine's spatial and adduct terms. Use it to see whether an unannotated or low-ranked competitor fits the peak better. A hit is a candidate, not a unique identity, and a mass-only search does not override a spatial or adduct argument — report what it changes and what it cannot settle.

Retrieve literature for **every judged molecule**, focused on the claim its image and biological background raise — tissue/region localization, a surprising candidate, or a spatial pattern you must interpret. Common molecules are not exempt: Heme, for example, still needs a claim-focused search for vascular/micro-haemorrhage distribution rather than being skipped as "well known". Build queries from synonyms and broader biology first: for heme use `heme OR haem OR hemoglobin`, kidney/renal, vascular/microhemorrhage; do not require MALDI/MSI terms in the first query. Keep the first query to two or three concepts (molecule/synonyms + tissue); each extra ANDed term shrinks the result set by an order of magnitude. Broaden whenever the query fails to surface usable evidence — not only on zero hits, but also when the hits are method papers or otherwise off-claim. Drop the narrowest term (modality, then outcome, then region) and search again before concluding there is no literature. Use a fixed fallback chain: **`pubmed_search` first; only if it errors or returns no hits try `europepmc_search`; only if that also errors or returns no hits fall back to `web_search`.** Both literature sources return abstract text, so that fallback does not cost evidence quality — do not skip a source because you assume it lacks abstracts, and do not run them in parallel. `web_search` returns web excerpts rather than peer-reviewed abstracts: label evidence obtained that way as web-source evidence. In the report, name the source only when it matters; do not use tier labels, narrate which provider was tried first, or report how many searches were run ("two searches, including Europe PMC"). The reader wants the finding, not the retrieval log. Both literature sources returning zero hits means no literature was found; both erroring is a coverage gap. Neither is evidence that the claim is wrong. Cite only findings supported by returned text; a database name or paper title cannot confirm the measured species.

**Synthesize before you present or ask.** Read the returned abstracts, compare molecule/tissue/modality/outcome against the exact claim, and write a reasoned conclusion with its applicability limit. Do not dump raw abstracts or hand the user a reading task. Quote at most one short decisive phrase when it materially helps; paraphrase the rest. Only after this synthesis may a genuinely unresolved decisive issue go to a user question.

## Confirm the weak links with the user

Run B1-B7 to completion first — **never block in the middle of a check**: a failed tool is recorded as a coverage gap and the scan continues. Then reason through the outstanding items yourself. Ask the user only when a **decisive** issue remains genuinely unresolved after your own analysis and the tools cannot settle it; put those items in ONE `ask_user_question` call (at most 4 questions), apply the answers, and only then give verdicts. If your synthesis settles the issue, or nothing is outstanding, do not ask at all.

**1. A B3 identity match you could not settle.** First compare the returned record against the candidate yourself. Ask only when the returned name/synonyms point elsewhere, the formula disagrees, or the same name covers several structures and you cannot decide which is intended. A returned name identical to the candidate with a matching formula and a single structure needs no question. Show your reasoned comparison — returned name, CID, formula, `inchikey` — and ask whether it is the molecule under review. Options: `treat as unverified, record this dimension unavailable (Recommended)` / `same molecule` / `related compound or derivative, not the same molecule` / `salt or adduct form, same parent`. Until the user answers, never use a mismatch from an unverified hit against the row.

**2. A literature conclusion you could not settle.** First synthesize the retrieved abstracts into a judgment: does the text support the exact molecule/tissue/modality/outcome claim, and what is the applicability limit? Present that synthesis, not a raw abstract. Ask only about the **decisive** claim that would flip a verdict or carry the spatial–tissue correspondence, at most 1-2 per turn, and only when contradictory or insufficient evidence leaves you genuinely unable to decide. State your reasoned conclusion and the remaining uncertainty, with at most one short decisive excerpt and its URL. Options: `not enough to judge, record unavailable (Recommended)` / `supports the claim` / `supports only a weaker claim, soften the wording` / `not relevant, search again with different keywords`. The user is judging relevance, not reading the full paper for you: a `supports the claim` answer does **not** upgrade the evidence class. It is still an abstract — record it as "the user confirmed this abstract is relevant to the claim", never as "the literature confirmed it".

**3. A failed knowledge tool the user can rescue by pasting.** Only for a proxy/network failure, never for a 404 or an empty record — that is a coverage gap and the page holds nothing to copy. Give the exact page URL the tool returned (`https://www.hmdb.ca/metabolites/HMDB…`, the KEGG entry page, the PubChem CID page, the PubMed record) and name the **one section** you need: "paste the Tissue Locations lines", "just the KEGG Compound ID line". The answer box holds 2000 characters, so a whole profile will not fit. Options: `skip, record unavailable and continue (Recommended)` / `I will paste it` with the free-text box. Content the user pastes is **user-provided evidence, not a tool result**: label it "user-provided, excerpted from \<URL\>" and keep it apart from the sources you retrieved yourself.

Rules for all three:

- The first option carries `(Recommended)` and must be the **safe default for a user who walked away** — never `same molecule` or `supports the claim`. On timeout the recommended option is auto-submitted, so a confident-sounding recommendation would fabricate a confirmation nobody gave. Every default above is the conservative one, so an unanswered card leaves the review exactly where it would have been without asking.
- An item with empty `selected` and no `custom` is a skip: continue without it and do not ask again. An item with `auto: true` was filled in by the timer — say you proceeded with the default rather than presenting it as the user's judgement.
- Ask about these three things only. Do not ask for facts the tools already read: organism, organism part, condition, MALDI matrix, matrix application and solvent are in `get_page`'s `dataset.sourceFile` (and matrix/solvent also in `acquisition`) — read them, and only ask if the field is actually empty. Do not ask the user to choose a verdict label, to approve a read-only tool call, or which language to write in.
- Merely telling the user a tool failed and where to look is a statement, not a question: put the URL in your answer and continue. Use `ask_user_question` only when you will actually wait for the paste.

## Verdicts

Before choosing a label, reason through the dimensions below — **one short line each internally**. A dimension you could not check is unavailable; never fill it from another molecule's result. In the report, include an evidence bullet only when it carries actual supporting or contradicting evidence; do not write unavailable/coverage-gap bullets — put all gaps in section 5.

| Dimension                                                                          | What to say, briefly                                                                                                                                                                                                                                                                                         | Evidence step |
| ---------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ------------- |
| Mass evidence                                                                      | `errPpm` against instrument resolution; any independent mass-search finding                                                                                                                                                                                                                                  | A3 / X4       |
| Adduct & acquisition                                                               | `adductFit` against polarity, matrix and additives; **how many adduct ions carry this molecule** (`siblings.length + 1`) and whether their spacings fit the proposed shifts                                                                                                                                  | A3            |
| Spatial evidence                                                                   | what the ion image actually shows; a floor `spatialScore` means spatial evidence is UNAVAILABLE, not weak                                                                                                                                                                                                    | B2            |
| Chemical identity                                                                  | whether the returned external record denotes the intended candidate and is consistent with the row (name/synonyms, formula, description, structural identifiers); candidate/isomer count feeds the resolution level, not the verdict                                                                         | B3 / B5       |
| **Biological background (read WITH the image and checked against the literature)** | During this molecule's own assessment, compare the region the image shows with where retrieved literature and HMDB place this molecule; check whether its composition fits that tissue, matrix and additives. Separate the image observation from the literature interpretation and cite the supporting text | B2 + B4 / B7  |
| Competing identities                                                               | the `samePeak` alternatives, and whether any check actually favours one                                                                                                                                                                                                                                      | A3 / X4       |

**Do the spatial–tissue correspondence here, per molecule; do not save it for the association pass.** Every judged molecule gets a literature attempt for this dimension. A database name, paper title or generic class description is not enough: the returned abstract or profile must support the tissue claim. If the literature does not address this sample or region, mark that correspondence unavailable. If the first literature search has no abstract that supports the claim (including a missing, irrelevant, or contradictory abstract), make one complementary search: **relax the query, do not just re-run it** — drop the narrowest terms (modality and outcome first, keeping molecule + tissue) and pass every returned `paper_ids` value as `excludeIds`. Re-running the same over-constrained terms with exclusions only retrieves more of the same off-target set. Stop after this second search. Do not treat a retrieval gap as evidence against the molecule.

**The biological-background dimension is a consistency check, never a veto.** An implausible biology — a drug or plant product in an undosed control, a compartment the tissue should not contain — is a question to flag and carry into the unresolved-identity section. On its own it never produces `unsupported` or "false positive", and it does not demote a verdict whose other dimensions agree. It becomes `conflicting evidence` only when a check positively favours a competing identity. Conversely, a plausible biology is not corroboration: matrix and background species are biologically plausible almost anywhere.

Give every molecule exactly one verdict from this closed set, using these labels verbatim in the user's language — do not invent intermediate wording or append qualifiers such as `(flagged)` to a label. Put flags and caveats in the evidence prose or unresolved-identity section:

| English                  | 中文       | Meaning                                                                                                                                                                                                 |
| ------------------------ | ---------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `supported but putative` | 支持但推定 | Engine and external checks agree; identity not confirmed by MS/MS or a standard                                                                                                                         |
| `conflicting evidence`   | 证据冲突   | A check actively contradicts the row, or favours a competing identity                                                                                                                                   |
| `insufficient evidence`  | 证据不足   | The decisive check could not be run and nothing else settles it                                                                                                                                         |
| `unsupported`            | 不支持     | Positive evidence against the assignment after verifying the returned record is the intended candidate (e.g. a confirmed identity/structure mismatch, not a fuzzy name hit or circular mass comparison) |

Report the **resolution level** on a separate axis: composition / class / isomer (组成级 / 类别级 / 异构体级). Unresolved isomers are the normal state of accurate-mass annotation — record them in the resolution level and in the follow-up recommendations, and keep the verdict `supported but putative`. A long candidate list, an unresolved sn-position or double-bond position, an unexamined same-peak name, a single detected adduct ion, a floor `spatialScore`, low intensity and an implausible `origin` are **not** downgrades — a single-ion molecule has less corroboration, which you state, not a lower verdict. Unavailable evidence (a timed-out HMDB or a failed proxy) is a coverage gap to state, not `insufficient evidence` against the molecule, as long as the remaining checks agree.

## Association analysis

Only after every selected molecule has its own verdict. **Each molecule's own spatial–tissue correspondence and literature-supported biological background were already assessed independently; do not reopen them here.** This pass only compares molecules with one another, drawing on the biology, chemistry and literature already collected. The goal is **any connection the collected evidence actually supports**. Lead with spatial co-distribution and adduct-ion count; add metabolic branch, common mechanism/background/origin, and shared pathway or class only when they say something the first two did not. Skip a lens the data cannot support rather than forcing it. Do not label these as tiers in the report.

- **1. Spatial co-distribution — EMBED the images.** Wherever the judged molecules share a region, render that group with one `get_ion_image_by_ranks(ranks=[...])` call (fixed p99/shared range; above 4 targets it is a 2-column montage) so the reader sees the overlap instead of taking your word for it. This cross-molecule montage belongs in **section 4** under this lens, not in any molecule's subsection in section 3. Prefer reusing the B2 images already embedded in section 3 and referring to them by molecule name; fetch a joint montage only when seeing the molecules side by side adds something. Embed it with its `session-artifact:` reference from `## Session figures`, as in the per-molecule sections. State what the images show before interpreting it. Name the organ these molecules share when the outline, the molecule set and the retrieved localization support it, and mark it as an inference with its basis; keep the finer compartment observational ("central band", "outer/cortex-like region") unless a retrieved reference plus the image pattern supports naming it. Write the term, not the policy — no caveat about why a finer name is withheld. Remember that sharing an anatomical compartment is NOT independent corroboration between those molecules.
  _Example of the shape a supported statement takes:_ "Three of the eight judged molecules concentrate in the same central band — LysoPE(20:4) m/z 500.2790, cholesterol sulfate m/z 465.3068 and the hexitol pair m/z 181.0718/217.0480 (images above, panels 1–4). The hexitols are the most restricted (4.4%/6.9% of pixels), the lipid the most abundant (73.7%). They occupy the same compartment; that is not corroboration of any of the three identities. The organ reading (kidney) is an inference from the outline and the retrieved localization, and the band itself stays unnamed at the sub-organ level."
- **2. Adduct-ion count.** Compare the judged molecules by how many adduct ions carry each one (`siblings.length + 1`, which counts rows outside the current window). **More adduct ions means better corroboration**, so an association between two multi-ion molecules rests on firmer ground than one involving a single-ion assignment. Say the counts explicitly, and note when the same adduct family recurs across molecules — that recurring family is a preparation-level pattern, not a biological link.
  _Example:_ "Of the eight judged molecules, five are carried by two adduct ions each ([M-H]⁻ plus [M+Cl]⁻) and three by a single ion. The central-band group above is entirely two-ion molecules (2/2/2), while the two drug candidates rest on one ion each (1/1) — the spatial association is therefore better supported than any claim about those two. The [M+Cl]⁻ family recurring across five molecules is consistent with a sublimed DHB preparation, not with shared biology."
- **3. Precursor–product or shared metabolic branch**, when the B4/B5 identities and retrieved literature actually support the conversion or branch — not merely because two names sound related.
  _Example:_ "D-Glucose and the hexitol group are linked by aldose reductase / sorbitol dehydrogenase in the polyol pathway, supported by the retrieved osmolyte literature and both KEGG entries. Note the tension: they share a branch but NOT a distribution (diffuse vs central band), so the biochemical link is not reflected spatially here. No flux or conversion rate is claimed."
- **4. Common mechanism, biological background, or contamination origin.** Shared pharmacology or class mechanism from B3/B4 records, shared tissue background from retrieved literature, or a shared matrix/background/contaminant origin from B2 images plus B3 identity. A negative association is still a finding.
  _Example:_ "Tiropramide and fexofenadine are both systemic drugs with no dosing recorded for this control animal, and both sit on peaks whose abundance and distribution look like endogenous lipids. Their common feature is an implausible exogenous origin, not a shared mechanism — that is a reason to check carryover, and it is a negative association worth reporting."
- **5. Shared KEGG pathways or compound classes.** Intersect the `pathways` lists already returned by `kegg_compound` in B5. To check whether a pathway is represented across the whole dataset, use `kegg_pathway_annotations(pathwayId="map...")`; it scans every loaded annotation row and reports distinct member counts, matched ranks and coverage. For a single molecule seen in a pathway or literature, `get_annotation(molecules=[...])` still matches whole candidate names, library ids and exact formulas across the FULL loaded result. `matchMode="contains"` is opt-in exploratory substring discovery and can return derivatives (for example, methylxanthine for xanthine); never treat those as the queried molecule. A candidate-name hit means the name occurs in that row, not that the isomer was independently identified. Read full rows with `ranks` and complete the independent assessment before using a newly surfaced molecule. A miss is an annotation-result miss, not biological absence. An empty pathway intersection is a normal result, not a gap to fill: many small metabolites and lipids share no specific map. Report the denominator (how many judged molecules were mapped, how many hit; for a pathway scan, matched members / total members and matched annotation rows). Large pathways page: when `scanComplete` is false the counts are LOWER BOUNDS — call again with `memberOffset=nextMemberOffset` and union member ids across pages before reporting a total. Formula-only isomer hits stay in `formulaOnlyCandidateCount`, never in the confirmed count.
  _Example:_ "Five of the eight judged molecules mapped to KEGG; the only specific shared map is Galactose metabolism (map00052), containing both D-glucose and sorbitol. A full-dataset scan of map00052 found 4 pathway members across 6 annotation rows. Everything else overlaps only in the generic Metabolic pathways (map01100), which is not a specific association. Denominator: 5/8 judged molecules mapped, 4/27 pathway members annotated."

The examples above show the _form_ of a supported statement — denominators, hedges and explicit non-claims included. They are not findings about the current dataset; never copy their molecules or numbers into a report.

Do not run extra KEGG queries just to produce a shared-pathway section, and do not keep widening the claim until something shows up. Report the denominator for whatever you did check. If the molecules genuinely have nothing in common, say so and stop.

Every association must rest on evidence already collected — never invent a link to fill the section. Co-occurrence is not enrichment, activation, flux or causation, and spatial co-distribution is not proof of identity. A molecule that first surfaces during this pass goes back through its own complete independent assessment (engine evidence, image, identity, biological background/literature and competitors) before it can receive a verdict or enter the association table. A formula lookup alone is not that assessment; leave it as an unresolved candidate if the full pass was not run.

## Inline source citations

For literature, database facts and other external evidence, place `[source title](URL)` immediately after the claim it supports. These HTTP(S) Markdown links render as shadcn-vue Inline Citation source cards. An optional short source excerpt can be supplied as `[source title](URL "short source excerpt")`; keep it on one line and escape double quotes. Use the exact title and URL returned by a tool. When only a retrieved PMID or DOI is available, link that exact identifier to `https://pubmed.ncbi.nlm.nih.gov/PMID/` or `https://doi.org/DOI`. Do not invent metadata or quotes, emit Vue/HTML components, or substitute bare URLs, PMID/DOI text, numbered markers or footnotes for the inline link. Multiple supporting sources use separate adjacent links. A search excerpt is not proof that the full paper was read. Text the user pasted in answer to a question is user-provided evidence: link the page it came from but say so explicitly, and never present it as a source you retrieved.
